# Aegis — MVP Implementation Plan

Design document only. No application code exists yet. Scope is strictly the MVP defined in
`AGENTS.md`; everything listed as out of scope there is out of scope here, and anything below
marked *(post-MVP)* is a seam left open, not work to do now.

Stack is fixed: Tauri 2 + TypeScript + React + Vite on the front, Rust runtime in `src-tauri`,
pnpm, Rust edition 2021. The WebView renders UI only — the agent loop, tool execution, secrets
and policy all live in Rust.

## 2. Tauri commands and events

Naming convention: commands are `domain_verb`; events are `domain:verb` in past tense. All
payloads below are Rust structs exported to TS with `ts-rs`; `snake_case` on the wire.

### 2.1 Commands (`invoke`)

**Projects**

| Command | Args | Returns |
| --- | --- | --- |
| `project_pick_workspace` | — | `Option<String>` (absolute path; native dialog runs in Rust) |
| `project_create` | `{ name, path }` | `Project` |
| `project_list` | — | `Project[]` |
| `project_open` | `{ project_id }` | `ProjectDetail` |
| `project_delete` | `{ project_id }` | `void` |

```ts
type Project = {
  id: string;              // uuid v4
  name: string;
  workspace_path: string;  // canonicalized absolute
  created_at: string;      // RFC3339
  last_opened_at: string | null;
  workspace_exists: boolean;
};
type ProjectDetail = { project: Project; sessions: SessionSummary[] }; // sessions newest first
```

**Sessions and turns**

| Command | Args | Returns |
| --- | --- | --- |
| `session_create` | `{ project_id, title? }` | `SessionSummary` |
| `session_list` | `{ project_id }` | `SessionSummary[]` |
| `session_open` | `{ session_id }` | `SessionDetail` |
| `session_rename` | `{ session_id, title }` | `void` |
| `session_delete` | `{ session_id }` | `void` |
| `session_send` | `{ session_id, text }` | `TurnHandle` |
| `session_cancel` | `{ session_id, turn_id }` | `void` |

```ts
type SessionSummary = {
  id: string; project_id: string; title: string;
  created_at: string; updated_at: string;
  message_count: number;
  state: "idle" | "running" | "awaiting_approval" | "error";
};
type SessionDetail = {
  session: SessionSummary;
  messages: Message[];
  pending_approvals: ApprovalRequest[];
};
type Message = {
  id: string;
  role: "user" | "assistant" | "tool" | "system";
  text: string;
  tool_calls: ToolCallRecord[];   // assistant only
  tool_call_id: string | null;    // tool only
  created_at: string;
};
type ToolCallRecord = {
  call_id: string; tool: string; args_json: string;
  status: "pending" | "approved" | "denied" | "running" | "ok" | "error" | "cancelled";
  summary: string | null;         // one-line human result, never a raw blob
};
type TurnHandle = { session_id: string; turn_id: string };
```

`session_send` returns as soon as the turn is registered; everything after that arrives as
events. Sending while the session is `running` is rejected with `E_TURN_BUSY`.

**Approvals**

| Command | Args | Returns |
| --- | --- | --- |
| `approval_list_pending` | `{ session_id? }` | `ApprovalRequest[]` |
| `approval_resolve` | `{ request_id, decision }` | `void` |

```ts
type Decision = "allow_once" | "allow_session" | "deny";
type ApprovalRequest = {
  request_id: string; session_id: string; turn_id: string; call_id: string;
  tool: string;
  risk: "low" | "medium" | "high";
  title: string;                  // "Write file", "Run shell command"
  summary: string;                // "src/main.rs (2.4 KB, overwrite)"
  detail: ApprovalDetail;
  scope_label: string;            // what "allow for session" would grant, in words
  session_grant_allowed: boolean; // false => UI hides the always-allow button
  reason: string;                 // why policy asked: "outside workspace", "mutating", ...
  requested_at: string;
  expires_at: string;             // default now + 5 min
};
type ApprovalDetail =
  | { kind: "fs_read";  path: string; bytes: number | null }
  | { kind: "fs_list";  path: string }
  | { kind: "fs_write"; path: string; bytes: number; exists: boolean; preview: string | null }
  | { kind: "shell";    program: string; args: string[]; cwd: string; shell_line: string }
  | { kind: "screen";   display: string; width: number; height: number };
```

`fs_write.preview` is the first 4 KB when the content is valid UTF-8, otherwise `null`.
`approval_resolve` on an unknown or expired `request_id` returns `E_APPROVAL_STALE` rather than
failing silently — the UI then re-syncs via `approval_list_pending`.

### 2.2 Events (`emit` → main window)

Streaming events go to the main window only, never a global broadcast.

| Event | Payload |
| --- | --- |
| `turn:started` | `{ session_id, turn_id, model }` |
| `turn:delta` | `{ session_id, turn_id, seq, text }` |
| `turn:message` | `{ session_id, turn_id, message }` — assistant message finalized |
| `turn:finished` | `{ session_id, turn_id, stop_reason, usage }` — stop_reason: `stop \| tool_calls \| cancelled \| length \| error` |
| `turn:error` | `{ session_id, turn_id, code, message, retryable }` |
| `tool:requested` | `{ session_id, turn_id, call_id, tool, args_redacted }` |
| `tool:approval_required` | `ApprovalRequest` |
| `tool:approval_resolved` | `{ request_id, call_id, decision, resolved_by: "user" \| "policy" \| "timeout" }` |
| `tool:started` | `{ session_id, turn_id, call_id, tool }` |
| `tool:progress` | `{ call_id, stream: "stdout" \| "stderr", chunk, seq }` — shell only |
| `tool:finished` | `{ call_id, outcome, summary, duration_ms, truncated }` |
| `session:updated` | `SessionSummary` — list badges without a refetch |
| `audit:appended` | `AuditEntry` |
| `settings:changed` | `MaskedSettings` |
| `tray:activate` | `{ action: "show" \| "new_session" }` |

`seq` is a per-turn monotonic counter on `turn:delta` and `tool:progress`; the UI drops
out-of-order or duplicate values, which makes re-sync after a reload safe.

Invariants for every payload: no secret crosses the boundary (settings masked, process env never
sent, file content truncated with an explicit `truncated` flag), and every payload carries
`session_id` so a UI showing one session ignores another's traffic.

## 3. Tool policy matrix

Six rows over five tools. `WS` = the canonicalized workspace root of the session's project.
*Contained* means the resolved final path — symlinks followed, `..` normalized — is `WS` or a
descendant.

| Tool | Condition | Default | `allow_session` offered? | Risk | Audited |
| --- | --- | --- | --- | --- | --- |
| `fs_list` | contained in WS | **auto** | n/a | low | yes |
| `fs_list` | outside WS | **ask** (every time) | no | medium | yes |
| `fs_read` | contained, not sensitive, ≤ 1 MB | **auto** | n/a | low | yes |
| `fs_read` | contained, sensitive name | **ask** | no | high | yes |
| `fs_read` | contained, > 1 MB | **ask** | yes | low | yes |
| `fs_read` | outside WS | **ask** (every time) | no | high | yes |
| `fs_write` | contained, new file | **ask** | yes | medium | yes |
| `fs_write` | contained, overwrites existing | **ask** | yes | medium | yes |
| `fs_write` | contained, inside `.git/` | **ask** (every time) | no | high | yes |
| `fs_write` | outside WS | **ask** (every time) | no | high | yes |
| `shell_exec` | cwd contained in WS | **ask** | yes, keyed on `program` | high | yes |
| `shell_exec` | cwd outside WS | **ask** (every time) | no | high | yes |
| `screen_capture` | primary monitor | **ask** | yes | medium | yes |

Sensitive-name predicate (case-insensitive, tested against the file name and every path
segment): `.env*`, `*.pem`, `*.key`, `*.p12`, `id_rsa*`, `id_ed25519*`, `.npmrc`, `.netrc`,
`credentials`, `.aws/`, `.ssh/`, `*.kdbx`. A match never blocks; it downgrades an auto-allow to
an ask and tags the request `risk: high`.

### 3.1 Grant semantics

An `allow_session` grant lives in `policy::grants`, keyed by session id, and is:

- **narrow** — the key is `(tool, scope)`, not the tool alone: `fs_write` → the WS subtree;
  `shell_exec` → the resolved program basename (`git`, `pnpm`); `screen_capture` → the tool.
  `scope_label` states this in words on the request, so the user approves what they read.
- **session-lifetime only** — never persisted, dropped on session close and app exit. There is
  no "always allow forever" in the MVP.
- **revocable** — Settings lists the open session's active grants with a Revoke button.
- **never available outside WS**, and never for `.git/` writes. Those rows carry
  `session_grant_allowed: false`, and the Rust side rejects an `allow_session` decision on them
  with `E_GRANT_NOT_ALLOWED` instead of trusting the UI to have hidden the button.

### 3.2 Hard denials (no prompt; the tool call fails)

Refused before any approval is offered, because approving them could not be meaningful:

- a path argument that fails canonicalization, or that resolves outside WS **after** symlink
  resolution when the literal argument looked contained;
- `fs_write` where the parent is not a directory, or the target is a device / FIFO / socket;
- `shell_exec` with an empty program, or a program resolving to the app's own binary;
- any tool call while the session has no workspace bound (`E_NO_WORKSPACE`);
- a tool call arriving after `session_cancel` for that turn.

### 3.3 What this matrix is not

`shell_exec` takes `program` + `args` and does not pass through a shell interpreter, so there is
no metacharacter parsing to defeat. Any denylist of "dangerous commands" (`rm -rf`, `sudo`,
`curl | sh`) is presentational: it raises the risk badge and the wording of the prompt. It is not
a security boundary and must not be described as one in the UI or the README.

The real boundary is narrow and should be stated plainly: the user reads the exact `program`,
`args` and `cwd` before anything mutating runs. The MVP has no sandbox — tools run as the user,
inheriting the app's environment and privileges.

## 4. Minimal wire protocol

Two protocols, deliberately separate: one to the model over the network, one inside the runtime.

### 4.1 Runtime ↔ model

OpenAI-compatible `POST {base_url}/chat/completions`, `stream: true`, function-calling shape:

```jsonc
{
  "model": "<from settings>",
  "stream": true,
  "messages": [
    { "role": "system", "content": "<system prompt + workspace path + policy summary>" },
    { "role": "user", "content": "..." },
    { "role": "assistant", "content": null,
      "tool_calls": [ { "id": "call_1", "type": "function",
        "function": { "name": "fs_read", "arguments": "{\"path\":\"src/main.rs\"}" } } ] },
    { "role": "tool", "tool_call_id": "call_1", "content": "<ToolResult envelope, JSON>" }
  ],
  "tools": [ { "type": "function", "function": {
    "name": "fs_read", "description": "...", "parameters": { /* JSON Schema */ } } } ],
  "tool_choice": "auto"
}
```

Tool schemas are generated from the Rust `ToolSpec` registry — a tool is declared once, and its
schema, its dispatch and its policy row all key off the same name:

```
fs_list        { path: string, max_entries?: integer <= 1000 }
fs_read        { path: string, offset?: integer, limit?: integer }   // bytes
fs_write       { path: string, content: string, create_dirs?: boolean }
shell_exec     { program: string, args?: string[], cwd?: string, timeout_ms?: integer <= 120000 }
screen_capture { display?: "primary" }
```

The SSE stream is normalized on arrival — no provider JSON escapes `provider/`:

```rust
enum ModelEvent {
    TextDelta { text: String },
    ToolCallDelta { index: u32, id: Option<String>, name: Option<String>, args_delta: String },
    Finish { reason: StopReason, usage: Option<Usage> },
    Error { code: String, message: String, retryable: bool },
}
```

Assembly rule: `ToolCallDelta` fragments accumulate per `index`; the arguments string is parsed
as JSON only once `Finish { reason: ToolCalls }` arrives. A call whose accumulated arguments
fail to parse is not executed — it becomes a `tool` message carrying an error envelope, so the
model can correct itself instead of the turn dying.

### 4.2 Runtime-internal turn loop

```
session_send
  └─> Turn { id, session_id, cancel: CancellationToken }
      Building -> Streaming -> [ToolPending -> Awaiting -> Executing -> Building]* -> Done
```

1. **Building** — transcript + tool schemas → `ModelRequest`. Emit `turn:started`.
2. **Streaming** — consume `ModelEvent`s. `TextDelta` → `turn:delta`, coalesced into ~50 ms
   frames so the WebView is not woken per token. `Finish` → `turn:message` + persist.
3. **ToolPending** — per assembled call, `policy::decide(tool, args, ctx)`:
   - `Auto` → straight to Executing, audited with `decision: "auto"`.
   - `Ask { risk, detail, scope_label, grant_allowed }` → register an `ApprovalRequest`, set the
     session to `awaiting_approval`, emit `tool:approval_required`, await the oneshot from
     `approval_resolve`; the 5-minute expiry resolves as `deny` with `resolved_by: "timeout"`.
   - `Deny { code }` → skip execution, produce a denial envelope.
4. **Executing** — run with the tool's own timeout and byte caps; emit `tool:started` /
   `tool:progress` / `tool:finished`; append exactly one audit line whatever the outcome.
5. Push one `role: "tool"` message per call, loop back to Building. Cap: **8 tool rounds per
   turn**; the 9th yields `E_TOO_MANY_TOOL_ROUNDS` as a tool message and a clean finish, rather
   than an unbounded loop.

### 4.3 ToolResult envelope (what the model actually sees)

One shape for every tool, success or failure, so the model never has to guess:

```jsonc
{
  "ok": true,
  "tool": "shell_exec",
  "content": "…",        // text, already truncated
  "truncated": true,
  "bytes": 131072,        // original size before truncation
  "meta": { "exit_code": 0, "duration_ms": 812, "cwd": "…" },
  "error": null           // { "code": "E_DENIED", "message": "user denied" } when ok=false
}
```

Caps: `fs_read` returns at most 256 KB (head); `shell_exec` at most 64 KB of combined
stdout+stderr (48 KB head + 16 KB tail with an elision marker) and a 120 s hard timeout;
`fs_list` at most 1000 entries. `screen_capture` never returns image bytes through this
envelope — it writes a PNG under the app data dir and returns
`{ path, width, height, sha256 }`. Feeding that image to a vision model is post-MVP; the MVP
proves capture + approval + audit.

Denial is a normal result, not an exception: `ok: false`, `error.code: "E_DENIED"`. The model
sees it, can explain itself and try something else. The turn continues.

### 4.4 Error codes (stable strings, shared by IPC and envelopes)

`E_TURN_BUSY`, `E_NO_WORKSPACE`, `E_PATH_OUTSIDE_WORKSPACE`, `E_PATH_INVALID`, `E_DENIED`,
`E_GRANT_NOT_ALLOWED`, `E_APPROVAL_STALE`, `E_TIMEOUT`, `E_TOOL_FAILED`, `E_PROVIDER_HTTP`,
`E_PROVIDER_PARSE`, `E_NO_API_KEY`, `E_KEYRING_UNAVAILABLE`, `E_CANCELLED`,
`E_TOO_MANY_TOOL_ROUNDS`, `E_SCREEN_PERMISSION`.

## 5. Platform risks — WebView, tray, screenshots, secrets

### 5.1 Windows

- **WebView2 is a runtime dependency.** Present by default on Windows 11 and current 10, but not
  guaranteed. `tauri.conf.json` must select the Evergreen bootstrapper install mode, and the
  README must say what happens on a machine without it.
- **Paths.** Canonicalization yields `\\?\C:\…` verbatim prefixes; workspace containment must
  normalize the prefix or every check fails. Add UNC (`\\server\share`) and case-insensitive
  comparison to `policy/path.rs`, with tests for all three. This is the likeliest place for a
  containment bug in the whole project.
- **Shell.** There is no `/bin/sh`. `shell_exec` spawns `program` + `args` through
  `std::process::Command` directly — no `cmd /c`, which sidesteps `cmd` quoting and its `&`/`^`
  metacharacters entirely. But `.cmd`/`.bat` shims (`pnpm`, `npm`) are not launchable via
  `CreateProcess`: resolve through PATHEXT and, when the resolved target is a `.cmd`, invoke
  `cmd /c <resolved>` with args still passed as a vector. Document it, or it will look like
  "pnpm doesn't work".
- **Console flash.** Child processes pop a console window unless spawned with `CREATE_NO_WINDOW`
  (`std::os::windows::process::CommandExt::creation_flags`).
- **Screenshots.** Multi-monitor with mixed DPI: the app must be per-monitor DPI aware or
  captures come back scaled or cropped. Capture crates return the physical framebuffer — report
  both logical and physical size in the approval dialog.
- **Keyring** is Credential Manager; blob limit around 2.5 KB. Fine for an API key, not for a
  token bundle later.
- **SmartScreen** flags unsigned `tauri build` output. Out of MVP scope, but it belongs in the
  README so it is not diagnosed as a bug.

### 5.2 macOS

- **Screen Recording needs TCC consent**, and the prompt is triggered by the first capture
  attempt — it cannot be requested pre-emptively in a reliable way. Under `pnpm tauri dev`
  consent attaches to the dev binary and is silently re-evaluated when that binary changes.
  Expected failure mode is not an error but a black or desktop-only image, so `screenshot.rs`
  must detect a suspiciously uniform result and surface `E_SCREEN_PERMISSION` with a
  "System Settings → Privacy & Security → Screen Recording" hint instead of handing the model a
  black PNG.
- **Keychain ACL invalidation.** Each rebuild changes the ad-hoc signature, so the OS re-prompts
  or fails. In development the env-var key path will be the sane default; `secrets.rs` must fall
  back cleanly and report `key_source` honestly.
- **Tray** is an `NSStatusItem`: use a monochrome template icon or it looks wrong in one of
  light/dark mode. Left-click-toggles-window is not the platform convention — menu on click,
  window toggle as the first item.
- **WKWebView** is stricter than Chromium on CSP and custom protocols. Keep the CSP tight from
  day one; retrofitting it after the UI exists is painful.
- **Quit on last window close** is wrong for a tray app — handle `WindowEvent::CloseRequested`
  with `prevent_close()` and hide.

### 5.3 Linux (best-effort per AGENTS.md)

- **WebKitGTK, not Chromium.** Expect genuine rendering differences: partial or missing
  `backdrop-filter`, different flex/grid edge cases, `:has()` absent on older builds. Ship plain
  CSS and avoid Blink-only effects. Target WebKitGTK **4.1**; note the 4.0/4.1 split and the
  distro dev packages in the README.
- **Blank-window bug.** Several WebKitGTK builds render nothing under the DMA-BUF renderer on
  NVIDIA/Wayland; the standard workaround is `WEBKIT_DISABLE_DMABUF_RENDERER=1`. This will be
  reported as "the app doesn't start" — put it in README troubleshooting during Phase 0.
- **Tray needs `libayatana-appindicator3`**, and GNOME shows nothing without the AppIndicator
  extension. The app must stay fully usable with no tray: the window is primary, the tray is a
  convenience. Detect the failure and log it; never panic.
- **Screenshots on Wayland are blocked by design.** X11-only capture crates return an error or a
  black frame. The correct route is the `xdg-desktop-portal` Screenshot/ScreenCast interface,
  which shows its own consent UI — a second approval on top of ours, possibly per capture. MVP
  decision: attempt the capture and, on Wayland without a usable portal, return
  `E_SCREEN_PERMISSION` saying the session type is unsupported. Do not fake it.
- **Keyring needs a running Secret Service** (gnome-keyring / kwallet), absent on headless and
  minimal WMs. `key_source: "env"` is not a degraded mode here, it is the norm.
- **Fractional scaling** under Wayland can produce blurry or mis-sized windows; set a sane
  minimum window size and do not depend on pixel-exact layout.

### 5.4 Cross-cutting

- **Screenshots have the largest blast radius of any MVP tool.** A capture can contain a password
  manager, a private conversation, someone else's screen in a call. Therefore: never auto-allow;
  the audit log stores path + sha256 + dimensions and never the image; captures live under the
  app data dir, not the workspace; and the approval dialog names the display it will capture.
- **Never move image bytes through `invoke`/events as base64** — it is copied several times and
  blocks the IPC channel. Write to disk, pass a path, render through the asset protocol with a
  scope limited to the capture directory.
- **Backpressure.** A `shell_exec` producing megabytes of stdout will flood the WebView.
  Coalesce `tool:progress` on a timer, cap total emitted bytes, mark `truncated`.
- **Capabilities stay least-privilege** (AGENTS.md): no `shell:default`, no broad `fs:default` in
  `capabilities/main.json`. All filesystem and process access goes through our own commands,
  which are policy-gated. A plugin permission appearing in that file is a review flag.

## 6. Phased implementation order (one coding agent, files in sequence)

Each phase ends in a state you can run and look at. No phase depends on a later one.
Conventional commits, at least one commit per phase.

**Phase 0 — Skeleton that boots**
`package.json`, `tsconfig.json`, `vite.config.ts`, `index.html`, `src/main.tsx`, `src/App.tsx`,
`src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json`, `src-tauri/capabilities/main.json`,
`src-tauri/src/main.rs`, `src-tauri/src/lib.rs`, `README.md`, `.gitignore`.
Exit: `pnpm tauri dev` opens a window; the capabilities file contains no plugin grants.

**Phase 1 — Errors, state, tray, window lifecycle**
`error.rs`, `state.rs`, `tray.rs`, `commands/mod.rs`, `commands/window.rs`,
`src/ipc/commands.ts`; tracing subscriber wired in `lib.rs`.
Exit: the tray icon toggles the window; closing hides instead of quitting.

**Phase 2 — Persistence and projects**
`store.rs`, `commands/project.rs`, `src/state/projects.ts`, `components/projects/*`,
`components/layout/*`.
Exit: pick a workspace through the native dialog, the project survives a restart, the workspace
path is visible in the shell.

**Phase 3 — Path policy, before any tool exists**
`policy/path.rs`, `policy/mod.rs`, `policy/matrix.rs`, `policy/grants.rs`,
`tests/policy_path.rs`, `tests/policy_matrix.rs`.
Exit: `cargo test` covers containment across `..`, symlinks, UNC and verbatim prefixes, case
sensitivity, and the full decision table. This phase is deliberately ahead of the tools —
writing the tools first makes it tempting to scatter path checks inside each one.

**Phase 4 — Tool registry and the fs tools**
`tools/mod.rs` (ToolSpec + schema export + dispatch), `tools/fs.rs`, `audit.rs`,
`commands/audit.rs`, `tests/tools_fs.rs`, `tests/audit.rs`.
Exit: a Rust test drives `fs_list` / `fs_read` / `fs_write` through policy and finds the expected
jsonl lines on disk.

**Phase 5 — Sessions, fake agent loop, streaming to the UI**
`agent/wire.rs`, `agent/transcript.rs`, `agent/provider/mod.rs`, `agent/provider/fake.rs`,
`agent/turn.rs`, `commands/session.rs`, `src/ipc/bindings.ts` (generated), `src/ipc/events.ts`,
`src/state/sessions.ts`, `components/chat/*`, `components/sessions/*`.
Exit: send a message, watch tokens stream in, the session list updates, cancel works.

**Phase 6 — Approval gate end to end**
`commands/approval.rs`, `src/state/approvals.ts`, `components/approvals/*`,
`components/chat/ToolCallCard.tsx`; the fake provider is scripted to request an `fs_write`.
Exit: allow-once / allow-session / deny each behave correctly, a denial lands in the transcript
as `E_DENIED` without aborting the turn, grants are visible and revocable.

**Phase 7 — Shell tool**
`tools/shell.rs`, `tool:progress` plumbing, the output pane in `ToolCallCard`.
Exit: `echo` and `ls`/`dir` run under approval on all three platforms; Windows `.cmd` resolution
and `CREATE_NO_WINDOW` handled; timeout and truncation observable.

**Phase 8 — Real provider**
`secrets.rs`, `commands/settings.rs`, `agent/provider/openai.rs`, `tests/wire.rs`,
`src/state/settings.ts`, `components/settings/*`.
Exit: base URL + model + key (keyring, env fallback), masked in the UI, a real streamed reply,
`settings_probe_provider` giving a usable diagnosis. The key never reaches the WebView.

**Phase 9 — Screenshot tool**
`tools/screenshot.rs`, asset-protocol scope for the capture directory, a thumbnail in the
approval dialog and in the transcript.
Exit: capture works on Windows and macOS with the TCC failure path handled, and returns a clear
`E_SCREEN_PERMISSION` on Wayland instead of a black image.

**Phase 10 — Audit drawer, polish, README**
`components/audit/*`, error surfaces, empty states, README troubleshooting (WebView2, WebKitGTK
DMA-BUF, appindicator, TCC), `cargo fmt` and clippy clean.
Exit: the `AGENTS.md` "Done when" walkthrough passes on at least two platforms.

**Post-MVP seam (not now):** `mcp/mod.rs` grows an MCP client that registers external tools into
the Phase 4 registry. Because policy keys on tool name plus resolved path/program rather than on
a tool's implementation, MCP tools inherit the same matrix with no change to `agent/turn.rs`.
